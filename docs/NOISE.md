# Noise Robustness Scorecard

本番経路 (LID→ルーティング→デコード→ja句読点) を、クリーン音声と white/pink/babble ノイズ (SNR 20/10/5/0dB) を重ねた音声の両方で評価。metricは en=WER, 他=CER（yueはt2s正規化）。

## ノイズ生成条件

- SNRは対象音声のRMSパワー基準: `10*log10(P_speech/P_noise) == SNR_dB`
- noise種別: white（ホワイトノイズ）, pink（1/fピンクノイズ）, babble（同一プールの別言語クリップを2〜3本ランダムに重ねた話し声ノイズ、対象と同言語は使用しない）
- SNRレベル: 20, 10, 5, 0 dB
- 乱数seed: 42（固定・再現可能、`scripts/make_noisyset.py` 参照）
- クリッピング防止: 混合波形のピークが1.0を超える場合は全体をスケールダウン
- 生成スクリプト: `scripts/make_noisyset.py` / 評価スクリプト: `scripts/eval_noise.py`

### 結論

ノイズ条件 60件中、denoiseでerrが改善したのは5件、悪化したのは52件、ほぼ変化なしが3件（平均Δerr=-0.051、正=改善）。 クリーン音声側の副作用: 平均Δerr=-0.018（悪化＝デノイザが健全な音声に悪影響）。 LIDは6件で悪化、5件で改善。 GTCRN自体のRTFは平均0.052と軽量。

**不採用が妥当**: ノイズ条件でも改善より悪化が多く、クリーン音声にも悪影響が出ている。前処理として常時オンにする根拠がない。

## LID頑健化: 二重判定ポリシー（dual-LID confirm）

### 崩壊メカニズム

`scripts/asr_engine.py` の `RoutedASR.transcribe()` は、セグメントごとに whisper-tiny ベースの
`SpokenLanguageIdentification` を1回呼んで言語タグを取得するだけで、確信度（confidence/logprob）は
sherpa-onnx の Python API 上に存在しない（`SpokenLanguageIdentification.compute()` は言語コードの
文字列しか返さない）。`docs/LID.md` で whisper-tiny 単独LIDの正解率をセグメント長別に実測したところ、
babble_snr10 条件では2秒で59%、clean条件でも2秒で61%しかなく、単発の誤爆でルーティング先の専用モデル
（ReazonSpeech/Paraformer/SenseVoice/v3/Omni）ごと変わってerrが跳ね上がる。さらに yue（広東語）は
whisper-tinyの出力語彙にCantoneseクラスが無いため、単独LIDでは原理的にzh系タグに丸められ続け、
どれだけ長い発話でも0%のまま。

一方、同じ `docs/LID.md` の測定で、whisper-tiny の判定とSenseVoiceの内蔵LID（`<|xx|>` タグ、
zh/yue裁定に既存コードが使っていた信号）が**一致した場合**の正解率は、babble_snr10で2秒85%・
2.5秒93%、cleanで2秒98%・2.5秒100%と、単独LIDを大きく上回る（一致率自体は低い場面もあるが、
一致したときの信頼性は極めて高い）。つまり「長さや連続回数」ではなく「2つの独立したLIDが
一致するかどうか」の方がはるかに強い切替シグナルになる。

### 採用ポリシー: 二重判定 + 従来ヒステリシスのハイブリッド

- SenseVoiceが対応する5言語（ja/en/zh/ko/yue）が候補として検出された場合: whisper-tinyの判定が
  セッションの現在言語と異なれば、**その場でSenseVoiceにも同じ音声をLIDさせ、両者が一致した場合のみ
  即座に切り替える**（長さ・連続回数の条件なし）。不一致なら現在言語を維持する。この判定ロジックは
  純関数 `resolve_dual_confirm()`（`scripts/asr_engine.py`）に切り出してあり、
  `tests/test_units.py` の `test_dual_confirm_*` 系テストでカバーしている。
- セッション先頭（現在言語が未確定）は、保留する「現在言語」がそもそも存在しないため、
  SenseVoiceプローブ自身の判定をそのまま採用する（プローブ単体でも表2の通り単独whisper-tinyより
  高精度なため）。これにより「先頭セグメントでwhisper-tinyが誤判定してもSenseVoiceが正しければ
  1発話目から正しい言語でデコードされる」を保証する。
- 0.5秒未満の極短候補は、SenseVoiceが一致してもノイズ（ジングル/SFX/瞬間的な誤爆）とみなし切り替えない。
- yue判定は既存の zh→SenseVoiceプローブ→yue裁定ロジックをそのまま維持（whisper-tinyの候補が
  "zh"のときは常にこの裁定を通す。二重判定が既にSenseVoiceをプローブ済みならその結果を再利用し、
  二重デコードを避ける）。
- SenseVoiceが対応しない言語（欧州語などv3/Omni行き）は、SenseVoiceで確認しようがないため、
  従来の長さ+連続確認ヒステリシス（`resolve_sticky_lang()`, `--lang-switch-guard` /
  `--lid-switch-confirm`）にフォールバックする。
- `--mode {single,balanced,fast}` で束ねて切替可能（`scripts/realtime_transcribe.py`）:
  `single` は `--lang` 固定でLID/切替ロジック自体を無効化、`balanced`（デフォルト）が上記の
  二重判定＋フォールバック、`fast` は二重判定を無効化し `--lid-switch-confirm 1 --lang-switch-guard 0`
  相当（whisper-tinyの検出をそのまま即切替）に相当する。個別の `--lang-switch-guard` /
  `--lid-switch-confirm` は明示的に渡せば `--mode` のデフォルト値を上書きする。

コンストラクタ引数 `dual_confirm: bool = True` / `forced_lang: str | None = None` として公開
（`RoutedASR.__init__`）。

### 結論

- **クリーン回帰ゼロを確認**: 5言語すべての clean 条件で LID正解率完全一致、err差も浮動小数点誤差の
  範囲内（±0.001未満）。
- 対象60条件（5言語 × white20/10/5/0・pink20/10/5/0・babble20/10/5/0）中、
  **LID正解率が改善したのは10条件、悪化したのは2条件、残り48条件は変化なし**。err も概ね連動して改善。
- **babbleでの改善が特に大きい**: yue（babble snr=0dB: LID 5/12→**12/12**、err -0.310）は
  `docs/LID.md` の予測どおり全回復した。whisper-tinyはyueを原理的に検出できないため
  旧ヒステリシスでは救えなかったが、二重判定はSenseVoiceのタグを直接使うため取りこぼさない。
  ja（babble snr=10dB: LID 12/15→15/15、err -0.148）も大きく改善。white/pinkでも
  ja white snr=5dB（11/15→14/15、err -0.154）、ja pink snr=0dB（13/15→14/15、err -0.128）など
  複数条件で改善。
- **悪化した2条件**: ja white snr=0dB（LID 13/15→12/15、err +0.059）と zh babble snr=0dB
  （LID 8/12→7/12、err +0.038）。ともにSNR=0dBという最も過酷な条件で、単発クリップの誤爆パターンが
  入れ替わっただけの揺らぎと見られ、影響幅も小さい。
- **総合判断**: 採用が妥当。改善条件数が悪化の5倍、悪化幅も軽微で最も過酷なsnr=0dB条件に限られる。
  クリーン音声の応答性は二重判定が一致すれば即時切替（旧来の最大1セグメント遅延より速い）。
  ポリシーの決定ロジックは `tests/test_units.py` の `resolve_dual_confirm` / `resolve_sticky_lang`
  系ユニットテストで retained。
